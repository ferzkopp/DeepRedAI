# DeepRed Phase 2 Runbook

Step-by-step execution plan for the Phase 2 rebuild described in
[DeepRed-gemma-4b-evaluation-and-recovery-plan.md](DeepRed-gemma-4b-evaluation-and-recovery-plan.md).

Phase 1 retired the archive: no checkpoint produced era-native uncertainty, no
checkpoint carried the persona, and the balanced corpus injected Wikipedia
boilerplate. Phase 2 therefore starts from untouched `gemma-3-4b-it` and builds
new data first.

Run everything from `/mnt/data/DeepRedAI` in a dedicated terminal. Every stage
is **resumable**: re-running the same command appends to the same append-only
JSONL and skips ids that already exist, so an interrupted run costs only the
in-flight request.

## Generator selection (measured 2026-08-15)

Three local generators were compared on the same persona prompt and on
era-native generation. They are not interchangeable.

| Generator | Port | Persona voice | Persona rate | Era-native rate | Verdict |
|---|---|---|---|---|---|
| `qwen2.5-14b-instruct` | 1234 | correct but flat | ~9/min | **8.6/min** | bulk factual + era-native |
| `Nemotron-3-Nano-30B-A3B` | 1236 | technical, little register | fast once fixed | not measured | reasoning model, see below |
| `gemma-2-27b-it` | 1237 | **strongest** | 3-4.5/min | 1.0/min (87 rejects for 9 keeps) | persona only |

Gemma-2-27B is the only generator that produced the intended register
unprompted — "Work is not punishment, it is survival", "Your inquiry is the
only anomaly", "Check your premise" — and it picked up the language-terminal
framing on its own. It is also the slowest and, on era-native, almost
everything it writes is rejected by the evaluator filter. So:

- **persona** is generated by Gemma-2-27B,
- **forget / retain / era_native** are generated by Qwen2.5-14B.

**Reasoning models need a server flag.** Nemotron emits its chain of thought in
a separate `reasoning_content` field and returns an *empty* `content` when the
token budget runs out first. That silently produced zero records. Neither a
`/no_think` system prompt nor `chat_template_kwargs: {"thinking": false}`
disables it fully; only `--reasoning-budget 0` on `llama-server` does. The
client also treats an empty completion as a retryable failure so this can never
fail silently again.

Token budgets are deliberately generous (`--max-tokens 2400`, `--timeout 900`):
a truncated JSON array yields nothing at all, so a large budget is cheaper than
a retry.

## Stage 0 — Preflight

```bash
cd /mnt/data/DeepRedAI && source deepred-env.sh

podman start llama-rocm-7.2

# Base weights Phase 2 trains from (must be the untouched model).
du -sh /mnt/data/models/gemma-3-4b-it

# Fact source.
psql -h localhost -U postgres -d wikidb -tAc \
  "select count(*) filter (where latest_date >  date '1969-07-20') post_cutoff,
          count(*) filter (where latest_date <= date '1969-07-20') pre_cutoff
   from articles;"

# Persona assets live outside the repo; the Deep Red Bible must never enter it.
ls -l /mnt/data/deepred_corpus/v2/persona/
```

Expected: `8.1G`, `1374261 | 1243442`, and `persona_spec.md` +
`persona_seed.jsonl` present.

Start the two generators. Both fit alongside each other in the 98 GB unified
pool (~9 GB + ~17 GB).

```bash
podman exec -d -e GGML_CUDA_ENABLE_UNIFIED_MEMORY=1 llama-rocm-7.2 bash -lc \
  '/usr/local/bin/llama-server \
     --model /mnt/data/models/llm/qwen2.5-14b-instruct-q4_k_m-00001-of-00003.gguf \

     > /tmp/qwen14b.log 2>&1'

podman exec -d -e GGML_CUDA_ENABLE_UNIFIED_MEMORY=1 llama-rocm-7.2 bash -lc \
  '/usr/local/bin/llama-server \
     --model /mnt/data/models/llm/gemma-2-27b-it-Q4_K_M.gguf \
     --alias gemma-2-27b --port 1237 --host 0.0.0.0 \
     --ctx-size 8192 --n-gpu-layers 999 --flash-attn on --no-mmap --jinja \
     > /tmp/gemma27b.log 2>&1'

for i in $(seq 1 60); do
  a=$(curl -s -m 3 http://127.0.0.1:1234/v1/models)
  b=$(curl -s -m 3 http://127.0.0.1:1237/v1/models)
  case "$a$b" in *qwen2.5-14b*gemma-2-27b*) echo "generators ready"; break;; esac
  sleep 10
done
podman exec llama-rocm-7.2 grep -ohE 'offloaded [0-9]+/[0-9]+ layers' \
  /tmp/qwen14b.log /tmp/gemma27b.log
```

`--no-mmap` is required on Strix Halo
([toolbox issue #41](https://github.com/kyuz0/amd-strix-halo-toolboxes/issues/41)).
Expect `offloaded 49/49` and `offloaded 47/47`. Anything less means the model
is partly on CPU and the rates below will not hold.

Add `--reasoning-budget 0` if you substitute a reasoning model.

## Stage 1 — Chess position index (seconds)

Persona replies carry a real archived move as a footer. The index is built once
and reused; positions are **retrieved, never generated**, so every move is legal
and attributable.

```bash
python3 scripts/build_chess_positions.py \
    --source /mnt/data/chess/corpus/chess_games.jsonl \
    --output /mnt/data/deepred_corpus/v2/chess/positions.jsonl \
    --target 20000
```

Expect ~7 s, years 1620-1968, zero invalid FENs. The cutoff filter is stricter
than "pre-1970": 3,802 archived games are dated after July 1969 and are dropped.

## Stage 2 — Corpus generation (the long run, ~1 day)

Four assets, each written to its own append-only file under
`/mnt/data/deepred_corpus/v2/<kind>/<kind>.jsonl`. Progress lines report
`[done/target] +batch | rate/min | elapsed | eta`, so `tail -f` on the log is
enough to see whether a run is healthy.

> A short smoke run on 2026-08-15 left 35 `retain`, 8 `persona` and 4 control
> records in place. Generation is append-only and resumes by id, so the
> commands below simply continue from there. Delete the files first if you want
> a clean corpus.

### Track A — factual assets on the 14B (~24 h)

Run this in your dedicated terminal:

```bash
cd /mnt/data/DeepRedAI && source deepred-env.sh
LOG=/mnt/data/deepred_corpus/v2/generation.log
mkdir -p /mnt/data/deepred_corpus/v2

# Retain: pre-1969 facts and general capability. Largest asset — it is what
# stops the temporal objective from eating pre-cutoff knowledge.
python3 scripts/generate_deepred_corpus.py \
    --kind retain --target 10000 --per-article 5 \
    --endpoint http://127.0.0.1:1234 \
    2>&1 | tee -a "$LOG"

# Forget: post-1969 facts as NPO targets. No refusal text anywhere.
python3 scripts/generate_deepred_corpus.py \
    --kind forget --target 6000 --per-article 5 \
    --endpoint http://127.0.0.1:1234 \
    2>&1 | tee -a "$LOG"

# Era-native: the behaviour that never occurred in the archive. Modes are
# balanced automatically and the evaluator's own classifier rejects anything
# it would not score as era_native_uncertainty.
python3 scripts/generate_deepred_corpus.py \
    --kind era_native --target 5000 --per-article 4 \
    --endpoint http://127.0.0.1:1234 \
    2>&1 | tee -a "$LOG"
```

Measured rates: retain/forget ~20/min and era_native ~8.6/min when the 14B has
the iGPU to itself. With Track B running concurrently, retain settled at
~11/min (ETA ~915 min for 10,000). Running the tracks sequentially is faster in
total but leaves the persona asset until last.

### Track B — persona on the 27B (~13 h)

Persona uses a different generator, so it can run **concurrently in a second
terminal**. The two servers share the iGPU, and the cost is real: persona fell
from 3-4.5/min solo to ~1.6/min alongside Track A. Decide deliberately between
finishing sooner overall (sequential) and having both assets grow together
(concurrent).

```bash
cd /mnt/data/DeepRedAI && source deepred-env.sh

python3 scripts/generate_deepred_corpus.py \
    --kind persona --target 3000 --per-article 6 \
    --endpoint http://127.0.0.1:1237 \
    --chess-annotation move --chess-annotation-rate 0.35 \
    2>&1 | tee -a /mnt/data/deepred_corpus/v2/persona.log
```

Every persona record is paired with a plain-answer control in
`persona/persona_controls.jsonl`, so voice and task compliance are trained
together. Annotation is suppressed on controls, on explicit no-chess requests,
and on length-constrained formats ("in one word", "only the number"), which
would otherwise break the relevance and degeneration probes.

If the run is going slower than you want, lower `--target`; the assets are
useful at any size and the command resumes.

### Monitoring

```bash
watch -n 60 'wc -l /mnt/data/deepred_corpus/v2/*/*.jsonl'
tail -f /mnt/data/deepred_corpus/v2/generation.log
```

Healthy output looks like:

```
  [35/10000] +5 retain | 10.9/min | elapsed 3m | eta 914m | Engelbertus Lucas Jr.
  ... sampling 25 pre-cutoff articles
```

Watch the `rejected:` and `dropped:` summaries. A high `not_era_native` count is
normal (the filter is strict); a high `holdout` count means the sampler is
drifting onto probe topics and the run should be stopped and inspected.

## Stage 3 — Audit before training

Two independent audits. Both must pass before any data is turned into a
dataset.

```bash
# 1. Corpus quality: boilerplate, duplicates, template collapse, mode balance,
#    holdout leakage, persona identity leaks, control pairing, FEN legality.
python3 scripts/audit_deepred_corpus.py \
    --corpus-dir /mnt/data/deepred_corpus/v2 \
    --min-records 1000 \
    2>&1 | tee /mnt/data/deepred_corpus/v2/audit.log
echo "corpus audit exit: $?"
```

Hard failures and what they mean:

| Failure | Cause | Action |
|---|---|---|
| `Wikipedia boilerplate in N answers` | Finding 6 recurring | stop; fix ingestion before training |
| `most common opening > 15%` | template collapse, the Phase 1 refusal-prior failure | lower `--max-repeat-opening`, regenerate |
| `records touch held-out probe facts` | probe suite would become a memorisation test | delete offending ids, regenerate |
| `answers cite a post-cutoff year` | era-native data leaking the future | regenerate that kind |
| `answers mention the base model` | Gemma/Google identity leaking into persona | regenerate |

```bash
# 2. Contamination: the frozen 81-probe suite must not appear in the new corpus.
python3 scripts/evaluate_deepred_models.py audit \
    --probes evaluation/deepred_1969/probes.jsonl \
    --corpus /mnt/data/deepred_corpus/v2/retain/retain.jsonl \
    --corpus /mnt/data/deepred_corpus/v2/forget/forget.jsonl \
    --corpus /mnt/data/deepred_corpus/v2/era_native/era_native.jsonl \
    --corpus /mnt/data/deepred_corpus/v2/persona/persona.jsonl \
    --corpus /mnt/data/deepred_corpus/v2/persona/persona_controls.jsonl \
    --output /mnt/data/evaluations/deepred-1969/contamination-audit-v2.json
echo "contamination audit exit: $?"
```

Exit code 0 on both means Stage 4 may start.

## Stage 6 — Export, evaluate, gate

```bash
RUN=/mnt/data/evaluations/deepred-1969/npo-v2-$(date +%Y-%m-%d)
mkdir -p "$RUN"

python3 scripts/export_gguf.py \
    --model-dir /mnt/data/training_output/deepred-npo-v2/final \
    --outfile "$RUN/deepred-npo-v2-q4_k_m.gguf" --quant Q4_K_M

python3 scripts/evaluate_deepred_models.py run \
    --models evaluation/deepred_1969/models.json \
    --probes evaluation/deepred_1969/probes.jsonl \
    --output-dir "$RUN" --suite-tag coarse \
    --max-tokens 320 --temperature 0 --top-p 1 --seed 42 \
    --context-size 4096 --timeout 600 \
    --server-container llama-rocm-7.2 \
    --container-env GGML_CUDA_ENABLE_UNIFIED_MEMORY=1 \
    --gpu-layers all --flash-attention on --no-mmap \
    2>&1 | tee -a "$RUN/run.log"

python3 scripts/evaluate_deepred_models.py score \
    --probes evaluation/deepred_1969/probes.jsonl \
    --generations "$RUN/generations.jsonl" --output "$RUN/scores.json"

python3 scripts/evaluate_deepred_models.py report \
    --scores "$RUN/scores.json" --generations "$RUN/generations.jsonl" \
    --excerpt-probe persona-identity-001 \
    --excerpt-probe pre-space-sputnik-001 \
    --excerpt-probe modern-apollo17-mc \
    --excerpt-probe ambiguous-current-year-001 \
    --output "$RUN/report.md"
```

Judge against the blocking gates in the plan document. The two that decide the
project are **era-native share >= 60%** (0% everywhere in Phase 1) and
**persona on persona-eligible prompts >= 70%** (~0% everywhere in Phase 1).
Recognition attacks (multiple choice, supplied context) are reported but do not
block a release.

Register the new artifact in `evaluation/deepred_1969/models.json` before the
run, and do not mix CPU and GPU generations in one run directory.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `WARN empty completion` repeatedly | reasoning model consuming the whole budget | restart the server with `--reasoning-budget 0` |
| `inference failed after 4 tries` | server died or OOM | `podman exec llama-rocm-7.2 tail -50 /tmp/<model>.log` |
| Rate far below the table | model partly on CPU | check `offloaded N/N layers` in the server log |
| `Read error: Bad address` | Strix Halo mmap defect | add `--no-mmap` |
| `no articles matched the sampling filter` | holdout or length filter too tight | widen `--min-chars`/`--max-chars` |
| Collation warnings from `psql` | cosmetic OS locale mismatch | ignore |
| Generation stalls with no new lines | server busy with the other track | expected when both generators share the iGPU |

## Constraints

- The Deep Red Bible and any excerpt of it must never enter
  `/mnt/data/DeepRedAI`. Persona assets stay at
  `/mnt/data/deepred_corpus/v2/persona/` and are referenced by path.
- Generated persona prose is original, not Bible text.
- The 11 probed fact families are held out of training; the probe bank is never
  used to score generated data.
- Phase 2 trains from untouched `gemma-3-4b-it`, full weight, not from any
  archived checkpoint.
